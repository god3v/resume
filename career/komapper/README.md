# [KoMapper 경력기술]

AI 기반 시설물 안전 점검 솔루션을 제공하는 B2B SaaS. Kotlin/Spring Boot 멀티모듈 MSA 백오피스에서 결제·구독·콘텐츠·인증 도메인 백엔드와 인프라를 담당.

## 요약

- **기간**: 2025.06 ~ 재직 중
- **역할**: 백엔드 엔지니어 (백엔드 개발 + GitOps/모니터링 인프라 + 릴리스 운영)
- **기술**: Kotlin, Spring Boot 3, JPA/QueryDSL, Axon Framework, Kafka, Redis, PostgreSQL, Spring Cloud Gateway(WebFlux), Kotest/MockK, Kubernetes(EKS)/ArgoCD, GitHub Actions
- **주요 성과**
  - 플랜 구독 결제 시스템을 요구사항 명세·데이터 모델링부터 구현·배포까지 풀사이클 수행
  - IP 기반 국가 판별을 인프라 제약(apex 도메인) 분석부터 게이트웨이·k8s 인프라까지 설계·구축
  - 모듈 간 이벤트 유실 문제를 재시도–영속화–알림 3단계 체계로 해결하고 9개 모듈에 확산
  - 클러스터 모니터링 스택(Prometheus·Loki·Promtail)과 신규 모듈 CI/CD·배포 인프라 구축
  - AI 기반 개발 워크플로우(개발 가이드·리뷰 체크리스트·SDD 스킬)를 팀 표준으로 문서화

## 주요 프로젝트

### 플랜 구독 결제 시스템 구축

- **기간**: 2026.04 - 2026.07
- **사용기술**: Kotlin, Spring Boot, JPA/QueryDSL, Axon Framework, Redis, PostgreSQL, Kotest/MockK
- **성과**: 토큰 단건 판매만 있던 서비스에 구독 판매 모델을 도입 — 설계 문서 15종(요구사항·논리/물리 모델·3채널 API 계약)과 백엔드 구현(PR 약 40건), 서비스·도메인 테스트 동반 개발

토큰 단건 판매 중심 서비스에 Seat 기반 구독 모델을 도입했다. 구현 착수 전 약 한 달간 요구사항 명세(SoT + 채널별 2종), 백엔드 플로우, 논리 모델(구독–회차–갱신–갱신상품 4단 구조), PostgreSQL 물리 모델(11개 테이블), 스케줄러 옵션 비교, 관리자/웹/솔루션 3채널 API 계약을 직접 작성하고, 이후 6주간 구현으로 옮겼다.

- 갱신 시 상품 구성이 바뀔 수 있어 회차별 청구 구성을 스냅샷으로 영속화하는 모델을 설계 — CS·정산 분쟁 대응의 근거를 남김
- 만료 상태를 DB에 저장하지 않고 만료일 기반 도출값으로 설계해, 상태 갱신 배치 지연·중복으로 인한 불일치를 구조적으로 제거
- 상태 전이(해지·결제실패·연장)를 도메인 함수로 캡슐화하고, 시트 증감 계획·응답 조립을 각각 도메인 모델과 Result 팩토리로 분리해 서비스 계층을 얇게 유지
- 관리자 콘솔(조직/구독/시트/수동 등록), 사용자 웹(통합 결제 내역/사용량), 솔루션 앱(인증/토큰 차감) API를 구현하고, 설계 문서를 구현과 동일 이슈 단위로 커밋 동기화해 스펙-코드 불일치를 방지
- QA에서 발견된 일할(proration) 과다 청구를 도메인 계산 기준 수정으로 해결하고 회귀 테스트로 고정

### 구독 갱신 재설계 — 선결제·만료 도래 배치

- **기간**: 2026.07
- **사용기술**: Kotlin, Spring Scheduler, TransactionTemplate, JPA 비관적 잠금, Kotest/MockK
- **성과**: 갱신을 "선결제 등록 + 만료 도래 배치 실행"의 2단계 모델로 재편해 만료~갱신 사이 서비스 사용 공백을 제거, 배치 중복 실행 시 이중 과금을 잠금+재확인으로 차단

수동 갱신이 즉시 만료일을 연장하는 기존 구조에는 선결제 개념이 없었고 갱신 시점 정의가 모호했다. "다음 회차 등록(선결제)"과 "만료 도래 시 배치가 소진해 갱신"으로 분리 재설계했다.

- 배치는 선결제 행을 비관적 잠금으로 잡고 잠금 획득 후 상태를 재확인 — 중복 실행 시 이중 갱신(이중 과금)을 차단
- 구독별 트랜잭션 격리로 한 구독의 실패가 전체 배치를 중단시키지 않도록 하고, 실패 건수 집계·로깅으로 운영 추적 확보
- 체험판 구독을 별도 서비스 포트로 분리하고 조직당 상품별 영구 1회 게이트 + 수동 등록 우회 차단 구현
- 주문 타입에서 역산하던 구독 분류를 명시적 속성 컬럼으로 전환하고, 클라이언트 지정 주문 타입을 서버 고정값으로 바꿔 위조 여지 제거
- 관련 설계 문서 12종을 같은 기간 일괄 정합화

### IP 기반 국가별 콘텐츠 제어

- **기간**: 2026.06 - 2026.07 (백엔드·인프라 담당)
- **사용기술**: Spring Cloud Gateway(WebFlux), MaxMind GeoIP2, AWS CloudFront/Global Accelerator, Kubernetes(initContainer·네이티브 사이드카), Loki
- **성과**: 국가 판별을 위조 불가능한 서버 권위 구조로 통일. 운영 도메인의 인프라 제약을 사전 조사로 규명하고 DNS 변경 없는 대안으로 전환해 dev→stg→prd 롤아웃

브라우저 locale로 국가를 유추해 가격이 잘못 노출되고, 클라이언트가 보낸 국가 코드를 그대로 신뢰해 위조가 가능하던 문제를 해결했다.

- 게이트웨이 GlobalFilter에서 인입 국가 헤더를 제거하고 공유 시크릿을 상수시간 비교로 검증, 판정 결과만 단일 헤더로 다운스트림에 전달 — 시크릿 미설정 시 fail-closed, 판정 불가 시 차단 대신 US 폴백으로 보안과 가용성을 함께 확보
- 운영 도메인이 apex(CNAME 불가)이고 DNS 사업자가 ALIAS를 미지원해 CloudFront를 붙일 수 없다는 제약을 배포 전 조사로 규명 — 대안 비교(Route53 존 위임/CloudFront 고정 IP/MaxMind) 후 Global Accelerator가 보존한 클라이언트 IP를 MaxMind로 조회하는 API 방식으로 전환
- GA의 클라이언트 IP 보존을 설정 확인에 그치지 않고 ALB 액세스 로그 마커 요청으로 실측 검증
- GeoIP DB를 mtime 폴링 + AtomicReference 원자 교체로 파드 재기동 없이 갱신(Hot Reload), 로드 실패 시 기존 리더를 유지해 서비스 연속성 확보
- k8s 배포는 initContainer(1회 다운로드, 실패해도 부팅 지속) + 네이티브 사이드카(주기 갱신) + Loki 로드 실패 알림으로 구성하고, 수동 배포되던 알림 설정을 ArgoCD Application으로 전환해 drift 제거

### MSA 이벤트 통신 신뢰성 체계

- **기간**: 2025.08, 2026.02
- **사용기술**: Axon Framework(RetryScheduler), Spring Kafka(RetryTopic/DLT), JPA, Slack Webhook
- **성과**: 모듈 간 이벤트 실패가 유실로 끝나던 문제를 재시도→DB 영속화→Slack 알림 3단계 체계로 해결, 공통 모듈 opt-in 방식으로 9개 전 모듈 적용

Axon Command·Kafka 이벤트가 실패하면 유실되고 원인 추적이 불가능했다.

- 재시도 스케줄러를 기존 구현을 감싸는 데코레이터로 설계하고, 커스텀 애노테이션 opt-in 방식의 공통 모듈로 만들어 모듈별 코드 변경을 최소화하며 확산
- 최종 실패는 payload를 JSON으로 영속화하고 Slack 알림 — 최종 실패 메시지는 사람이 봐야 할 원인이 대부분이라 자동 재발행 대신 인지 시간 단축에 집중, 수동 재처리(스킵 상태 전이)를 확장 지점으로 설계
- Kafka는 RetryTopic(지수 백오프)에 비재시도 예외(역직렬화 오류·무결성 위반 등)를 분류해 무의미한 재시도 없이 즉시 DLT로 보내도록 구성
- dev 환경 replicas 조정으로 수신 모듈 다운을 실제 재현해 저장·알림 동작을 검증
- 스키마 분리 환경의 모듈 간 데이터 결합은 DB 조인 대신 Axon Command 배치 조회로 처리해 모듈 경계 유지

### 콘텐츠 도메인 모듈 분리 — 뉴스·공지·Q&A

- **기간**: 2026.02 - 2026.04
- **사용기술**: Kotlin, Spring Boot, QueryDSL, Axon, OWASP java-html-sanitizer, GitHub Actions, Kubernetes
- **성과**: 계정 모듈에 혼재된 콘텐츠 기능을 독립 배포 가능한 모듈로 분리(이관 약 4,800줄·잔여 제거 약 3,000줄), CI 3환경 파이프라인과 무중단 배포 구성까지 완결

- content 모듈을 신규 스캐폴딩하고 뉴스·공지 전 계층을 이관, 이관과 동시에 Kotest 테스트 약 2,000줄을 추가해 회귀 안전망 확보
- 단순 1:1 문의-답변(상태 2종) 구조를 5종 상태 머신·스레드형 대화로 재설계 — spec·API 계약 문서를 먼저 작성해 기획 리뷰를 거친 뒤 구현
- 작성자 정보를 별도 모델로 구조화해 탈퇴자 개인정보 마스킹 규칙을 일원화, 총판 관할 문의에 대한 본사 개입 차단
- 리치 에디터 본문의 XSS를 화이트리스트 sanitizer로 차단, 확장자 기반 MIME 오판별을 매직 바이트 판별로 교체
- 무중단 배포 매니페스트(maxUnavailable 0, preStop, probe 3종)를 작성해 dev→stg→prd 순차 롤아웃

### 총판(파트너) 관리자 인증·권한 체계

- **기간**: 2025.11 - 2025.12
- **사용기술**: Kotlin, Spring Security, JWT, Redis, JPA
- **성과**: 총판 관리자 온보딩(계정 생성→링크 토큰 검증→활성화)과 인증·역할 기반 권한 체계를 신규 구축, 정책 변경 시 폐기 코드 757줄을 3개 모듈에서 일괄 제거

- 총판 인증을 콘솔에서 전용 partner 모듈로 분리하고 JWT Provider·시크릿 키를 독립 구성해 키 유출 영향 범위 격리
- 고정 Enum 권한 판정을 역할-권한 매핑 테이블 기반으로 전환해 역할 단위의 유연한 권한 관리 구조로 개선
- 초기 비밀번호 설정 링크 토큰을 Redis 만료로 관리하는 온보딩 플로우 구축
- 셀프 회원가입 정책이 폐기되자 직접 구현했던 관련 경로 전체를 제거해 잔존 코드 없이 정리 — 프론트 병행 개발을 위한 Mock API 선제공 후 실구현 교체 방식 사용

### 결제 도메인 — 쿠폰·환불

- **기간**: 2025.06 - 2025.09
- **사용기술**: Kotlin, JPA, QueryDSL, Axon, PortOne(PG), Kotest/MockK/H2
- **성과**: 쿠폰 도메인 신규 구축과 PG 환불 시스템·환불 정책 구현, 테스트가 전무하던 payment 모듈에 계층별 테스트 기반 최초 구축

- 쿠폰 도메인(관리자/사용자 분리, 엔티티 상속 구조)을 구축하고 주문 결제 금액 계산과 통합, 흩어진 할인 규칙(주문/상품 × 정액/정률)을 전략 패턴으로 단일화
- PG 환불 연동에 환불 수수료 유예·취소 기한 정책을 도메인 모델로 캡슐화하고, PG 에러 응답 타입별 매핑과 예상 금액 일치 검증의 이중 안전장치 구성
- 프로모션 쿠폰 사용 시 모듈 간(payment→license) 처리를 Axon Command로 설계, 토큰 지급의 중복 방지는 사용 쿠폰 ID 존재 가드로 처리
- Kotest(DescribeSpec)+MockK+H2 계층별 테스트와 공용 픽스처 패턴을 최초 구축 — 이후 신규 모듈 테스트의 표준으로 확산
- 요청 파라미터의 사용자 ID를 신뢰하던 API를 JWT 인증 주체 기반으로 전환

### API Gateway — 인증·안정성·단일 세션

- **기간**: 2025.07 ~ (상시)
- **사용기술**: Spring Cloud Gateway(WebFlux/Reactor), Spring Security Reactive, Redis, JJWT
- **성과**: 사용자 유형별 인증 필터 체계 위에 단일 세션 강제·에러 표준화·재시도 범위 한정을 구현

- 활성 시트 사용자의 다중 디바이스 동시 사용을 게이트웨이 필터로 차단 — Redis 저장 토큰과 매 요청 비교하되, 키 부재 시 통과시키는 설계로 레거시 사용자 하위 호환을 별도 마이그레이션 없이 확보
- 다운스트림 장애(503) 시 표준 JSON 에러 응답으로 변환하는 전역 핸들러 구현, 5xx 전체에 걸리던 재시도 필터를 503 한정으로 수정해 비멱등 요청의 중복 처리 위험 제거
- 블로킹 호출(Redis·내부 검증)을 boundedElastic 스케줄러로 격리해 이벤트 루프 보호

### 모니터링 · GitOps 인프라

### dev 클러스터 노드 OOM 인시던트 대응

- **기간**: 2026.07
- 배포 중 신·구 JVM 공존으로 단일 노드 물리 메모리 고갈 → kubelet 사망 → NodeNotReady 전파. EC2 재부팅과 cordon/uncordon으로 복구하고, 원인을 메모리 request 과소·limit 오버커밋으로 규명해 재발 방지 방안(request 현실화, 배치 분리) 도출

### 구조 개선 리팩토링

- 쿠폰 할인 규칙을 전략 패턴으로 통합(주문/상품 × 정액/정률의 분산 로직 단일화)
- 어댑터(Axon CommandHandler)에 있던 결제 생성 로직을 Application Service로 이관 — 어댑터는 입출력 변환만 담당하는 헥사고날 원칙 정비
- 상품·플랜 조회의 N+1 쿼리를 QueryDSL fetch join 단일 쿼리로 전환
- 계층 역할이 드러나는 매퍼 네이밍 컨벤션(WebMapper/PersistenceMapper) 확립
