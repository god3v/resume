프로젝트 개요

토큰 단건 판매만 존재하던 서비스에 구독 판매 모델을 도입. 요구사항 명세, 데이터 모델, 관리자/웹/솔루션 3채널 API 계약을 직접 작성하고 백엔드 구현과 배포까지 수행

팀 구성 및 역할

  • 요구사항 명세·데이터 모델·API 계약 작성부터 백엔드 구현과 배포까지 단독 수행

주요 업무

  • 구독–회차–갱신–갱신상품 구조로 데이터 모델을 설계해 회차별 청구 구성과 갱신 이력을 명시적으로 영속화
  • 관리자/웹/솔루션 3채널 API 계약 작성 및 구현
  • 설계 문서와 구현 코드를 동일 이슈 단위로 커밋 동기화해 스펙-코드 불일치를 방지

문제 해결 과정

  • 만료 상태의 구조적 정합성 확보
    • 만료 상태를 DB에 저장하지 않고 만료일 기반 도출값으로 설계해 상태 갱신 누락으로 인한 불일치를 구조적으로 제거
    • 해지·연장 등 상태 전이는 도메인 함수로 캡슐화해 규칙 수정 지점을 단일화
  • 수동 갱신의 2단계 모델 재설계
    • 즉시 만료일을 연장하던 수동 갱신을 선결제 등록 + 만료 도래 배치의 2단계 모델로 재설계해 만료~갱신 사이 서비스 사용 공백을 제거
    • 배치는 구독별 트랜잭션 격리로 개별 실패의 전파를 막고, 비관적 잠금 후 재확인으로 중복 실행 시 이중 갱신을 방지
  • 청구 정확성과 위조 여지 제거
    • QA에서 발견된 일할(proration) 과다 청구를 도메인 계산 기준 수정으로 해결하고 회귀 테스트로 고정
    • 체험판 도입으로 부정확해진 주문 타입 역산 분류를 구독 자체 속성 컬럼으로 전환하고, 클라이언트가 지정하던 주문 타입을 서버 고정값으로 바꿔 위조 여지를 제거
  • 조회 최적화
    • 상품 목록의 건별 상세 조회(N+1)를 QueryDSL fetch join 단일 쿼리로 전환

기여 성과

  • 토큰 단건 판매만 있던 서비스에 구독 판매 모델을 명세부터 배포까지 완결 도입
  • 상태 갱신 누락 불일치·이중 갱신·일할 과다 청구 등 정합성 리스크를 구조적으로 제거
  • 클라이언트 지정 값을 서버 고정값으로 전환해 주문 타입 위조 여지 제거

클라이언트 신뢰 국가 판정을 게이트웨이 서버 권위 판정으로 전환

Spring Cloud Gateway, MaxMind GeoLite2, AWS Global Accelerator, k8s, ArgoCD, Loki

프로젝트 개요

브라우저 locale로 국가를 유추해 가격이 잘못 노출되고, 클라이언트가 보낸 국가 코드를 그대로 신뢰해 위조가 가능하던 문제를 게이트웨이 서버 권위 판정 구조로 해결

팀 구성 및 역할

  • 제약 분석과 대안 설계 문서화부터 구현·배포 구성까지 단독 수행

주요 업무

  • 게이트웨이 GlobalFilter 기반 국가 판정 필터 설계·구현
  • MaxMind GeoLite2 IP 조회와 GeoIP DB Hot Reload 구현
  • initContainer·사이드카·Loki 알림을 포함한 k8s 배포 구성과 dev→stg→prd 롤아웃

문제 해결 과정

  • 서버 권위 판정 구조 설계
    • 게이트웨이 GlobalFilter에서 인입 국가 헤더를 제거하고 검증된 값만 단일 헤더로 전달하도록 설계
    • 공유 시크릿은 상수시간 비교로 검증하고, 시크릿 미설정 시 fail-closed·판정 불가 시 차단 대신 US 폴백을 택해 보안과 가용성을 함께 확보
  • 인프라 제약 분석과 대안 설계
    • 운영 도메인이 apex(CNAME 불가)라 CloudFront 국가 헤더를 쓸 수 없는 제약을 배포 전 조사로 규명
    • Global Accelerator가 보존한 클라이언트 IP를 MaxMind GeoLite2로 조회하는 API 방식으로 전환 — 제약 분석과 대안 설계를 문서로 남기고 직접 구현
  • GeoIP DB Hot Reload
    • 주기 갱신되는 GeoIP DB 반영을 위해 파드 재기동 대신 파일 변경 감지(mtime 폴링) + AtomicReference 원자 교체의 Hot Reload를 구현
    • DB 로드 실패 시에도 부팅을 막지 않고 기존 리더를 유지해 서비스 연속성 확보
  • 배포 파이프라인 정비
    • initContainer(1회 다운로드) + k8s 네이티브 사이드카(주기 갱신) + Loki 로드 실패 알림 구성을 dev→stg→prd로 롤아웃
    • 수동 kubectl로 배포되던 알림 설정을 ArgoCD Application으로 전환해 구성 drift 제거

기여 성과

  • 브라우저 locale 기반 가격 오노출과 클라이언트 국가 코드 위조 가능성 제거
  • fail-closed·US 폴백 설계로 보안과 가용성을 함께 확보
  • 파드 재기동 없는 GeoIP DB 갱신으로 서비스 연속성 확보, ArgoCD 전환으로 구성 drift 제거

    • dev 환경 replicas 조정으로 실패 시나리오를 실제 재현해 동작 검증
  • 모듈 경계 유지

  • 실패 메시지 유실 방지와 원인 추적 체계 확보
  • 커스텀 애노테이션 opt-in·데코레이터 설계로 모듈별 코드 변경을 최소화하며 9개 전 모듈 적용
