액션

  • 구독 도메인 설계

    • 만료 상태를 DB에 저장하지 않고 만료일 기반 도출값으로 설계해 상태 갱신 누락으로 인한 불일치를 구조적으로 제거, 해지·연장 등 상태 전이는 도메인 함수로 캡슐화
  • 갱신의 2단계 모델 재설계
    • 즉시 만료일을 연장하던 수동 갱신을 선결제 등록 + 만료 도래 배치의 2단계 모델로 재설계해 만료~갱신 사이 서비스 사용 공백을 제거
    • 배치는 구독별 트랜잭션 격리로 개별 실패의 전파를 막고, 비관적 잠금 후 재확인으로 중복 실행 시 이중 갱신을 방지
  • 청구 정확성과 위조·우회 여지 제거
    • QA에서 발견된 일할(proration) 과다 청구를 도메인 계산 기준 수정으로 해결하고 회귀 테스트로 고정

  • 쿠폰·환불 도메인 구축

10주간 이커머스 백엔드를 단계적으로 구축 — 단순 CRUD를 넘어 설계·동시성·성능·회복탄력성·이벤트·유량 제어·실시간/배치 집계까지 실제 서비스의 문제를 직접 해결

핵심 기술

  • 헥사고날 아키텍처 기반 멀티모듈 구성 (api·streamer·batch·pg-simulator 독립 운영) — 도메인은 프레임워크 비의존 순수 Kotlin으로 유지
  • 도메인별 맞춤 동시성 제어 — 재고 차감은 비관적 락 + ID 정렬 조회로 데드락 회피, 결제 정산은 거래 식별자 기준 락으로 콜백·폴링 직렬화, 랭킹은 Redis Lua 원자 실행
  • 외부 PG 장애 격리 — 타임아웃·재시도·서킷브레이커 적용, Transactional Outbox Pattern으로 이벤트 발행 원자성 보장
  • Redis 기반 주문 대기열 유량 제어, 랭킹은 일간 실시간(ZSET 누적)·주간/월간 사전 집계(Spring Batch)로 이원화
  • TDD 기반 개발, Testcontainers(MySQL·Redis·Kafka) 통합 테스트, k6 부하 측정을 근거로 인덱싱·캐싱 최적화
