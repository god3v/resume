프로젝트 개요

토큰 단건 판매만 존재하던 서비스에 구독 판매 모델을 도입. 요구사항 명세, 데이터 모델, 관리자/웹/솔루션 3채널 API 계약을 직접 작성하고 백엔드 구현과 배포까지 수행

팀 구성 및 역할

  • 요구사항 명세·데이터 모델·API 계약 작성부터 백엔드 구현과 배포까지 단독 수행

주요 업무

  • 구독–회차–갱신–갱신상품 구조로 데이터 모델을 설계해 회차별 청구 구성과 갱신 이력을 명시적으로 영속화
  • 관리자/웹/솔루션 3채널 API 계약 작성 및 구현
  • 설계 문서와 구현 코드를 동일 이슈 단위로 커밋 동기화해 스펙-코드 불일치를 방지

문제 해결 과정

  • 만료 상태의 구조적 정합성 확보
    • 만료 상태를 DB에 저장하지 않고 만료일 기반 도출값으로 설계해 상태 갱신 누락으로 인한 불일치를 구조적으로 제거
    • 해지·연장 등 상태 전이는 도메인 함수로 캡슐화해 규칙 수정 지점을 단일화
  • 수동 갱신의 2단계 모델 재설계
    • 즉시 만료일을 연장하던 수동 갱신을 선결제 등록 + 만료 도래 배치의 2단계 모델로 재설계해 만료~갱신 사이 서비스 사용 공백을 제거
    • 배치는 구독별 트랜잭션 격리로 개별 실패의 전파를 막고, 비관적 잠금 후 재확인으로 중복 실행 시 이중 갱신을 방지
  • 청구 정확성과 위조 여지 제거
    • QA에서 발견된 일할(proration) 과다 청구를 도메인 계산 기준 수정으로 해결하고 회귀 테스트로 고정
    • 체험판 도입으로 부정확해진 주문 타입 역산 분류를 구독 자체 속성 컬럼으로 전환하고, 클라이언트가 지정하던 주문 타입을 서버 고정값으로 바꿔 위조 여지를 제거
  • 조회 최적화
    • 상품 목록의 건별 상세 조회(N+1)를 QueryDSL fetch join 단일 쿼리로 전환

기여 성과

  • 토큰 단건 판매만 있던 서비스에 구독 판매 모델을 명세부터 배포까지 완결 도입
  • 상태 갱신 누락 불일치·이중 갱신·일할 과다 청구 등 정합성 리스크를 구조적으로 제거
  • 클라이언트 지정 값을 서버 고정값으로 전환해 주문 타입 위조 여지 제거

프로젝트 개요

브라우저 locale로 국가를 유추해 가격이 잘못 노출되고, 클라이언트가 보낸 국가 코드를 그대로 신뢰해 위조가 가능하던 문제를 게이트웨이 서버 권위 판정 구조로 해결

팀 구성 및 역할

  • 제약 분석과 대안 설계 문서화부터 구현·배포 구성까지 단독 수행

주요 업무

  • 게이트웨이 GlobalFilter 기반 국가 판정 필터 설계·구현
  • MaxMind GeoLite2 IP 조회와 GeoIP DB Hot Reload 구현
  • initContainer·사이드카·Loki 알림을 포함한 k8s 배포 구성과 dev→stg→prd 롤아웃

문제 해결 과정

  • 서버 권위 판정 구조 설계
    • 게이트웨이 GlobalFilter에서 인입 국가 헤더를 제거하고 검증된 값만 단일 헤더로 전달하도록 설계
    • 공유 시크릿은 상수시간 비교로 검증하고, 시크릿 미설정 시 fail-closed·판정 불가 시 차단 대신 US 폴백을 택해 보안과 가용성을 함께 확보
  • 인프라 제약 분석과 대안 설계
    • 운영 도메인이 apex(CNAME 불가)라 CloudFront 국가 헤더를 쓸 수 없는 제약을 배포 전 조사로 규명
    • Global Accelerator가 보존한 클라이언트 IP를 MaxMind GeoLite2로 조회하는 API 방식으로 전환 — 제약 분석과 대안 설계를 문서로 남기고 직접 구현
  • GeoIP DB Hot Reload
    • 주기 갱신되는 GeoIP DB 반영을 위해 파드 재기동 대신 파일 변경 감지(mtime 폴링) + AtomicReference 원자 교체의 Hot Reload를 구현
    • DB 로드 실패 시에도 부팅을 막지 않고 기존 리더를 유지해 서비스 연속성 확보
  • 배포 파이프라인 정비
    • initContainer(1회 다운로드) + k8s 네이티브 사이드카(주기 갱신) + Loki 로드 실패 알림 구성을 dev→stg→prd로 롤아웃
    • 수동 kubectl로 배포되던 알림 설정을 ArgoCD Application으로 전환해 구성 drift 제거

기여 성과

  • 브라우저 locale 기반 가격 오노출과 클라이언트 국가 코드 위조 가능성 제거
  • fail-closed·US 폴백 설계로 보안과 가용성을 함께 확보
  • 파드 재기동 없는 GeoIP DB 갱신으로 서비스 연속성 확보, ArgoCD 전환으로 구성 drift 제거

프로젝트 개요

모듈 간 Axon Command·Kafka 이벤트가 실패 시 유실되고 원인 추적이 불가능하던 문제를 해결

팀 구성 및 역할

  • 실패 처리 공통 모듈의 설계·구현과 전 모듈 적용 담당

주요 업무

  • 재시도 → 실패 영속화 → Slack 알림으로 이어지는 3단계 실패 처리 공통 모듈 구현
  • Kafka RetryTopic·Dead Letter Topic 핸들러 구성
  • 모듈 간 데이터 결합을 Axon Command 배치 조회로 표준화

문제 해결 과정

  • 3단계 실패 처리 공통 모듈
    • 재시도(1초 간격 3회) → 최종 실패 DB 영속화 → Slack 알림의 3단계 처리를 공통 모듈로 구현하고, 커스텀 애노테이션 opt-in 방식으로 9개 전 모듈에 적용
    • 재시도 스케줄러는 기존 구현을 감싸는 데코레이터로 설계해 모듈별 코드 변경 최소화
  • Kafka 재시도·DLT 체계
    • Kafka RetryTopic(지수 백오프, 비재시도 예외 분류)과 Dead Letter Topic 핸들러를 구성
    • dev 환경 replicas 조정으로 실패 시나리오를 실제 재현해 동작 검증
  • 모듈 경계 유지
    • 스키마가 분리된 모듈 간 데이터 결합을 DB 조인 대신 Axon Command 배치 조회로 처리해 모듈 경계를 유지 (쿠폰 사용자 조회, Q&A 작성자 조회, 구독-결제 결합 등에 일관 적용)

기여 성과

  • 실패 메시지 유실 방지와 원인 추적 체계 확보
  • 커스텀 애노테이션 opt-in·데코레이터 설계로 모듈별 코드 변경을 최소화하며 9개 전 모듈 적용
  • 실제 장애 시나리오 재현 검증으로 재시도·DLT 동작의 신뢰성 확보

기여 성과

  • CI·무중단 배포 구성까지 포함해 분리를 배포 단위로 완결
  • 탈퇴자 마스킹 규칙 일원화와 XSS·MIME 검증으로 콘텐츠 보안 강화

프로젝트 개요

본사 외 총판 관리자라는 새 사용자 유형의 계정·인증·권한 체계를 구축

팀 구성 및 역할

  • 총판 관리자 계정·인증·권한 체계의 설계·구현 담당

주요 업무

  • 총판 전용 partner 모듈 분리와 JWT Provider·시크릿 키 독립 구성
  • 역할-권한 매핑 테이블 기반 권한 체계 전환
  • 계정 생성 → 링크 토큰 검증 → 활성화로 이어지는 온보딩 플로우 구축

문제 해결 과정

  • 인증 격리

  • 권한 구조 개선
    • 고정 Enum으로 판정하던 관리자 권한을 역할-권한 매핑 테이블 기반으로 전환해 역할 단위 권한 관리가 가능한 구조로 개선
  • 온보딩 플로우와 폐기 코드 정리
    • 계정 생성 → Redis 만료 관리 링크 토큰 검증 → 활성화로 이어지는 온보딩 플로우를 구축
    • 셀프 회원가입 정책이 폐기되자 직접 구현했던 관련 코드 757줄을 3개 모듈에 걸쳐 일괄 제거해 폐기 경로의 잔존 코드를 남기지 않음

기여 성과

  • 인증 분리·시크릿 독립 구성으로 키 유출 영향 범위 격리
  • 고정 Enum 판정에서 벗어나 역할 단위 권한 관리가 가능한 구조 확보
  • 폐기 정책 관련 코드 일괄 제거로 폐기 경로의 잔존 코드 미보유

결제 도메인 — 쿠폰·환불

쿠폰 도메인 신규 구축과 PG 환불 연동, 테스트 기반 최초 확립

Kotlin, Spring Boot, 포트원(PG), Kotest/MockK/H2

프로젝트 개요

결제 도메인에 쿠폰 할인과 PG 환불 정책을 도입하면서, 흩어진 할인 규칙과 환불 오처리 위험, 테스트 부재 문제를 함께 해결

팀 구성 및 역할

  • 쿠폰·환불 도메인 설계·구현과 payment 모듈 테스트 기반 구축 담당

주요 업무

  • 쿠폰 도메인(관리자/사용자 분리, 엔티티 상속 구조) 신규 구축과 주문 결제 금액 계산 통합
  • PG(포트원) 환불 연동과 환불 정책 도메인 모델링
  • Kotest+MockK+H2 기반 계층별 테스트와 공용 픽스처 패턴 구축

문제 해결 과정

  • 쿠폰 도메인 구축과 할인 규칙 단일화
    • 쿠폰 도메인(관리자/사용자 분리, 엔티티 상속 구조)을 신규 구축하고 주문 결제 금액 계산과 통합
    • 서비스와 모델에 흩어진 할인 규칙(주문/상품 × 정액/정률)을 전략 패턴으로 단일화해 규칙 변경 지점을 한 곳으로 축소
  • PG 환불 연동의 이중 안전장치
    • PG(포트원) 환불 연동에 환불 수수료 유예 7일·취소 기한 90일 정책을 도메인 모델로 캡슐화
    • PG 에러 응답 타입별 매핑과 예상 금액 일치 검증의 이중 안전장치로 환불 오처리를 방지
  • 테스트 기반 최초 구축
    • 테스트가 전무하던 payment 모듈에 Kotest+MockK+H2 기반 계층별 테스트와 공용 픽스처 패턴을 최초 구축 — 이후 신규 모듈 테스트의 표준으로 확산
  • 인증 우회 가능성 제거
    • 요청 파라미터의 사용자 ID를 신뢰하던 API를 JWT 인증 주체 기반으로 전환

기여 성과

  • 흩어져 있던 할인 규칙의 변경 지점을 전략 패턴으로 한 곳으로 축소
  • 에러 매핑·금액 검증 이중 안전장치로 환불 오처리 방지
  • 테스트가 전무하던 모듈에 구축한 테스트 패턴이 신규 모듈 테스트의 표준으로 확산
  • 요청 파라미터 신뢰 API를 JWT 인증 주체 기반으로 전환해 인증 우회 가능성 제거

    • Redis INCR + TTL 기반 카운팅으로 1분 단위 동일 실패 유형 집계, 500건 초과 시 Kafka 토픽에 장애 알림 발행
  • 비동기 알림 처리

  • 월별/일별 발송 건수·실패 내역 통계 집계 및 조회 시스템 구축

프로젝트 개요

고객사가 발송 결과 확인을 위해 API를 주기적으로 호출(Polling)하던 방식이 실시간성이 떨어지고 불필요한 트래픽을 유발해, Push 방식의 콜백 기반 발송 결과 통지 시스템을 설계·구현

팀 구성 및 역할

  • Push 방식 콜백 통지 시스템의 설계·구현 담당

주요 업무

  • Kafka 기반 발송 결과 수신 및 처리
  • WebFlux 기반 비동기 Push 시스템 구축
  • 발송 실패 대응 및 장애 감지 체계 구축

문제 해결 과정

  • 비동기 Push 처리
    • Redis에 저장된 고객사 콜백 URL을 조회해 WebClient로 비동기 HTTP 요청 전송
    • Reactor 패턴 적용으로 대량 트래픽 환경에서도 높은 처리량 유지
  • 실패 대응·폴백 설계
    • Exponential Backoff 방식의 재시도 로직 적용
    • 최종 실패 시 DLQ로 전송해 기존 Polling 방식으로 결과를 가져갈 수 있도록 폴백 구성

기여 성과

  • Push 전환으로 불필요한 Polling 트래픽 절감 — API 호출 횟수 30% 감소
  • 비동기 처리·재시도 로직으로 Push 처리 성공률 99% 유지 (실패율 1% 미만)
